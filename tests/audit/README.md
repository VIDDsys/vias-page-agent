# 历史审计脚本

本目录保留早期审查和故障复现材料，不属于当前版本的自动化质量门槛。源码结构、动作协议和浏览器测试路径已经变化；不能把旧脚本的通过、失败或统计直接解释为当前产品的结论。

当前验证在源码目录执行：

```bash
npm run check
npm run test:all
```

`test:all` 使用 `tests/` 根目录中的现行测试，覆盖模型协议、任务隔离、页面执行、扩展加载、界面反馈及敏感字段。本目录不进入桌面分发副本。

## 适用边界

| 脚本 | 用途与限制 |
| --- | --- |
| `dead-code.js` | 只读名称引用扫描。注释、字符串、同名声明和测试引用都可能影响计数；结果只作人工调查线索，不证明没有死代码。 |
| `contract-audit.cjs` | 依赖旧常量、提示词格式和快照结构的历史检查器。检测不到原有源码布局时以退出码 `2` 报告“审计器不适配”，不继续输出误导性的契约通过或失败。即使源布局匹配，也需人工复核正则提取结果。 |
| `probe-dom-coverage.js` | 历史页面覆盖探针，含旧正文预算和 iframe 假设；不是当前能力验收。异常清理不完整，运行前需核对和补齐。 |
| `stress-extreme-pages.js` | 历史极端页面探针，读取旧 `snapshotMeta` 字段；输出的“完整”不能证明当前快照未截断。 |
| `stress-extreme-actions.js` | 历史动作压力用例，部分预期已失效，例如把未支持的 `image` 动作期待为缺少目标。 |
| `vias-approval-leak-repro.js` | 旧审批逻辑的漏洞复现，期待旧审批漏洞出现；不能用于现行无审批卡片版本。 |
| `vias-deep-audit-repro.js` | 旧提交权限规则的故障复现；断言描述的是历史行为。 |
| `vias-stale-agent-repro.js` | 旧错误文案的代理故障复现；未维护为当前恢复流程回归。 |

## 维护原则

运行历史浏览器探针前，先核对目标版本、源码路径、协议预期和异常清理。仅使用临时浏览器配置、本地页面和假模型，不读取日常配置或调用付费接口。三个 `vias-*-repro.js` 的源码根按脚本自身位置解析（`path.resolve(__dirname, '../..')`），不依赖固定绝对路径。

修复现行缺陷时，把可重复的最小场景加入 `tests/` 根目录的对应测试。若要恢复历史审计器为现行门槛，应先更新提取规则并验证规则本身；源模式缺失必须报告审计器失配，不能按空集合相等显示通过。
