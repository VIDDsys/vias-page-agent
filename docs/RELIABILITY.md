# 执行可靠性与已知边界

适用版本：0.15.0。本文区分页面实际变化、执行器的动作结果和任务最终确认，避免把本地回归测试当作所有网站的现场根因证明。

## 延迟翻译与目标变化

浏览器翻译或文字改写扩展可能先让助手读取原文，再延迟改写题干、选项、按钮文字或节点结构。读取时与操作时的页面因而不同，旧编号可能被拒绝为 `STALE_TARGET`。

本轮用户实测确认，延迟翻译是此前现场问题的触发源。此前项目中的动态页面 fixture 只能证明相应边界能够发生，不能代替该现场结论。自动刷新、前端框架重绘和翻译改写也不能一概视作同一类变化。

进行自动操作前，暂停目标页面上的自动翻译或文字改写，或等待页面完成翻译后再开始任务。不要仅为避开报错而删除题干、标签或选项值的身份校验。

`STALE_TARGET` 不总能证明点击从未发生：变化可能出现在点击之前，也可能发生在点击后的结果核验阶段。重新执行前应参考当前选中状态和操作记录，避免盲目重复提交。

## 保留的执行策略

| 场景 | 当前处理 | 保留原因 |
| --- | --- | --- |
| 无关节点抖动、选中状态、焦点或明确的状态提示变化 | 不仅因此拒绝正常目标 | 这些变化通常不改变用户要操作的对象 |
| 同题、同值选项的等价重绘 | 在原路径及身份校验通过后恢复当前控件 | 允许常见框架重建节点，不按旧位置盲目点击 |
| 题干、真实标签、选项提交值、关联控件或题目归属变化 | 拒绝旧目标并要求重读 | 防止同节点被复用到另一题或另一个选项 |
| 同文档仅个别目标失效 | 对失效目标返回 `STALE_TARGET`，有效目标继续按批次规则执行 | 避免无关变化使整批失败 |
| URL、文档或 `snapshotId` 已失效 | 拒绝旧快照 | 不在新页面重放旧操作 |
| 相同 `operationId` 重复到达 | 复用已有结果 | 防止通信重试造成重复副作用 |

新 `EXTRACT` 会使旧快照编号失效。因此，“先提取、再提取、最后使用第一次快照执行”属于快照失效，不应将该测试误解为一次普通文字变化必然使整批失效。

## 动作结果的含义

- `click` 表示对解析后的原目标派发点击。点击导致页面更新、提交或导航本身可以是正常结果；不能仅因事后文字不同就认定点击了错误对象。
- `check`、填写和选择会额外核对对应状态或实际保留值。身份在确认阶段改变时，可能返回失败或未确认，即使此前已产生一次点击。
- 页面稳定检测有有限等待窗口。它无法保证网站或其他扩展在任意更晚时间都不改写内容；无限延长等待会使普通任务变慢，也无法给出永久稳定保证。
- 工具成功不等于服务端业务已经最终完成。异步校验、登录失效、网站只接受可信物理输入等情况仍需结合页面状态判断。

本轮复核未取得新的跨题误点证据，也没有据延迟翻译这一线索继续放宽或收紧上述规则。

## 为什么仍可能显示未确认

后台按目标身份、动作意图及必要参数保留未解决的失败。无关操作成功不能消除它；同批原计划后续动作的成功也不能补偿前面少执行的动作。

选择控件额外使用不透明 `choiceIdentity`，使同一节点换题或换值后不会被当作原操作恢复。原始题干和值不反射进该标记。

以下情况保持保守：

- 重新读取只看到“已经选中”，没有足够证据关联之前的失败。
- 重试返回 `NO_CHANGE`，但它不足以证明此前未确认的操作已经得到核实。
- 重绘产生新节点，或旧内容脚本缺少可比较的身份标记。
- 非幂等操作通信中断，无法判断此前是否已产生副作用。
- repeat 失败归属缺失，或未解决证据超过有界集合容量。

这些条件可能让任务实际状态正确而最终结果仍为 `unverified`。这是避免虚报成功的取舍；界面应提示核对，不把它描绘成已证实的错误操作。

未来如改进这部分，应增加按动作类别定义的可观察状态证明：例如同一字段的完整值、同题同选项的选中状态及提交后的明确结果。不能仅靠模型宣告完成、任意成功动作或 `NO_CHANGE` 清除失败。本版本没有新增这类通用目标验证器。

## 执行上限与前端边界

执行模式默认最多 100 次观察/操作循环，外部请求不能将该上限放得更高。已确认完成时会提前结束；相同操作连续三次页面无变化、交替操作连续四次无变化、连续失败、防重复执行和用户停止仍可更早终止。只读问答的最终回答预算保持原设计，分段读取另有有界预算。

同一对话中开始新任务时，侧栏会把上一任务的动作与失败结果（有界摘要）作为上下文交给模型，模型不必依赖用户复述就能知道此前执行过什么、哪些失败。该记录只进入模型请求，不显示在聊天正文，新建对话时清空。

内部计数继续用于任务协调与幂等处理。侧栏不显示轮次数字，工具框只显示操作类型或操作数量；输入区上方显示当前工作状态。达到上限时使用不含轮数的提示。

本轮以界面重构为主。执行内核仅按用户新要求调整默认及最大循环上限，模型请求、页面定位、目标恢复、任务绑定、失败判定与取消逻辑保持原样。

## 验证结论的范围

项目测试使用隔离 Edge、本地模型接口和可重复的模拟页面，覆盖协议、任务隔离、导航、动态选项、长文本、表单、停止、设置竞态及敏感字段。

通过这些测试说明已覆盖场景符合约定，不表示所有真实模型服务和业务网站都已验证，也不构成“达到极致”或“零缺陷”的承诺。继续改进应以明确复现、可观察结果和回归证据为依据，避免在未知现场原因上不断增加校验或回退规则。
